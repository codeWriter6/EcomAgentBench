# EcomAgentBench：面向电商数据分析的智能体任务评测基准

**EcomAgentBench**（*E-commerce Agent Benchmark*）是与论文《基于多智能体的数据驱动型电商业务分解与执行框架》相关的公开电商数据分析任务评测基准。基准面向关系型数据库分析场景，包含任务分解、SQL 查询、结构化数据处理、定量分析与报告生成等任务要求，可用于比较静态工作流和多智能体等不同方法的任务完成能力。

---

## 1. 基准概述与设计原则

**EcomAgentBench** 共包含 **160 个结构化数据分析任务**，涵盖单表订单数据集（**Orders**）与多表关系型电商数据集（**Olist**）两类数据源，设置 **16 个任务族**（每个数据集 8 个任务族，每族 10 个参数变体），并按计算结构复杂度划分为**简单（40 题）**、**中等（40 题）**与**困难（80 题）**三个等级。

本基准将每个任务的输入分为三个部分：

1. **自然语言业务请求（`query`）**：采用符合真实用户提问习惯的自然语言句式描述业务分析目标。
2. **公开业务统计口径（`business_rules`）**：将不可省略的确定性业务定义（筛选范围、时间窗口开闭边界、统计分母、单位换算、缺失值与零分母处理规则）整理为独立的条目列表，对所有参评方法同等公开，减少因业务口径歧义导致的评测偏差。
3. **结果表与报告交付约束（`output_contract` / `delivery_contract`）**：明确规定目标结果表的列顺序、数据类型、排序规则、唯一键约束，以及独立分析报告的章节结构与证据引用核验要求，为结果格式校验和独立评测提供明确依据。

## 2. 数据集与任务族划分

### 2.1 数据集说明

| 数据集标识 | 数据源说明 | 表结构规模 | 主要评测侧重点 | 题数 |
| :--- | :--- | :--- | :--- | ---: |
| **Orders** (`millat_orders_local`) | 开源电商订单数据集 `millat/e-commerce-orders` 本地快照 | 单表（`orders`），10,000 条记录、15 个字段 | 单表条件过滤、日期与分箱变换、实体层级嵌套聚合、客户序列邻接分析与跨期排名稳定性 | 80 |
| **Olist** (`olist_sqlite_local`) | 巴西公开电商关系型数据集（Olist Brazilian E-Commerce） | 9 张关系表（订单、明细、支付、评价、客户、卖家、商品等），共 1,550,922 行 | 多表关联查询、一对多分支预聚合（防止连接基数放大）、跨表金额对账、集中度指数（HHI）与评分关联分析 | 80 |

### 2.2 难度划分标准与任务族清单

任务难度依据得到正确结果所必需的逻辑运算与依赖结构预先设定，不依赖特定方法实际生成的节点数或运行准确率：

- **简单（`simple`，40 题）**：单表查询，仅涉及局部条件筛选、单行属性提取或数值分箱及单层分组聚合，不包含跨行依赖或多表连接。
- **中等（`medium`，40 题）**：包含时间戳合法性校验与时长计算、同粒度跨表维度关联后聚合，或按月汇总后的相邻期环比计算（不再叠加更高层级聚合）。
- **困难（`hard`，80 题）**：至少包含以下一种复杂计算结构：① 实体级汇总后与同群均值/总额比较并二次汇总；② 实体内部按时间序列排序、构造相邻订单对后再过滤与统计；③ 跨时间窗口分别计算商品销售额排名（Top-$K$）并通过 Jaccard 相似系数衡量榜单集合的相似程度；④ 两个独立的一对多明细分支分别预聚合至订单粒度后再关联汇总。

| 数据集 | 任务族 ID (`family_id`) | 业务分析主题 | 必要逻辑计算结构 | 难度等级 | 参数变体设置（每族 10 题） |
| :--- | :--- | :--- | :--- | :---: | :--- |
| **Orders** | `orders_weekday_amount` | 星期订单量与销售额对比 | 筛选 $\to$ 星期提取 $\to$ 分组计数与金额求和 | 简单 | 6 类商品品类 + 4 类营销渠道 |
| **Orders** | `orders_quantity_bands` | 订单购买数量分档分布 | 筛选 $\to$ 单笔数量分箱 $\to$ 分档统计 | 简单 | 6 类商品品类 + 4 类营销渠道 |
| **Orders** | `orders_shipping_latency` | 各配送状态发货等待时长 | 日期非空与先后校验 $\to$ 天数差计算 $\to$ 状态分组均值/极值 | 中等 | 6 类商品品类 + 4 类营销渠道 |
| **Orders** | `orders_monthly_movement` | 月度订单规模与金额环比 | 月度汇总 $\to$ 前一有效月份对齐 $\to$ 环比计算与零分母处理 | 中等 | 6 类商品品类 + 4 类营销渠道 |

## 3. 单题数据结构规范

`cases.json` 中的每个任务对象包含以下字段：

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `id` | `string` | 任务唯一标识符 |
| `source_task_id` | `string` | 任务编号 |
| `dataset` / `dataset_id` | `string` | 数据集简称（`orders` / `olist`）及对应本地数据库标识 |
| `family_id` | `string` | 所属任务族标识 |
| `type` | `string` | 任务难度等级：`simple`、`medium` 或 `hard` |
| `split` | `string` | 数据集划分标识 |
| `query` | `string` | 面向用户的自然语言业务分析请求 |
| `business_rules` | `array<string>` | 公开的业务统计口径与边界规则 |
| `required_columns` / `required_fields` | `array<string>` | 结果表必须输出的字段名及顺序 |
| `output_contract` | `object` | 结果表的结构约束，包括字段类型、空值要求、取值范围、排序规则及唯一性约束 |
| `delivery_contract` | `object` | 任务结果的交付与校验规则，包括输出格式、数值比较容差及分析报告要求 |
| `benchmark_version` | `string` | 基准标识，固定为 `EcomAgentBench` |

## 4. 任务使用与公平对比说明

本仓库以 **`cases.json` 中公开的任务定义** 为主要发布内容。

每个任务的 `query` 描述业务分析目标，`business_rules` 给出必要的统计口径，`output_contract` 和 `delivery_contract` 指定结果格式与交付要求。研究者可以根据这些字段构建自己的运行输入，但应明确记录实际提供给模型的信息及其组织方式。

在使用本基准比较不同方法时，建议遵循以下原则：

1. **输入信息一致**：各方法应获得相同任务的 `query`、`business_rules` 及适用的输出约束。
2. **执行条件统一**：尽可能统一数据库快照、模型及推理参数；对无法统一的设置单独说明。

### 数据来源

- **Orders**：[`millat/e-commerce-orders`](https://huggingface.co/datasets/millat/e-commerce-orders)，Hugging Face 上公开的合成电商订单数据集，数据页标注许可证为 MIT。
- **Olist**：[`Brazilian E-Commerce Public Dataset by Olist`](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce)，Kaggle 上公开的匿名化巴西电商订单数据集，数据页标注许可证为 CC BY-NC-SA 4.0。

本题集的表结构和行数说明来自所使用的本地数据版本。第三方研究如重新下载、导入或清洗原始数据，可能因版本、预处理与 SQLite 类型转换差异而得到不同结果。

## 6. 版本、引用与使用边界

- **公开基准名称**：`EcomAgentBench`（E-commerce Agent Benchmark）。
- **标准结果**：本仓库不发布参考 SQL 或标准结果。
- **测试集使用**：使用公开任务进行提示词优化、开发或训练时，应在后续评测论文中披露，以便读者判断潜在测试集泄漏或过拟合风险。

如发现任务描述或统计口径错误，建议通过仓库 Issues 反馈。涉及任务结果变化的修订，应更新版本并保留变更说明。
